# Test principles

Use the principles as decision constraints, not slogans.

1. **Testing shows the presence of defects.** Report confidence and observed evidence; never claim defect absence.
2. **Exhaustive testing is impossible.** Select conditions using product risk, representative partitions, boundaries, states, and scenarios.
3. **Early testing saves time and cost.** Review requirements, acceptance criteria, interfaces, and testability before implementation is treated as complete.
4. **Defects cluster.** Expand analysis and regression around defect-prone, complex, frequently changed, or highly coupled surfaces.
5. **Tests wear out.** Refresh data, techniques, negative paths, and regression selection when the same suite repeatedly supplies little new information.
6. **Testing is context dependent.** Adapt levels, types, techniques, independence, and evidence to the product and risk.
7. **Absence-of-errors is a fallacy.** A green technical suite is insufficient when the product does not satisfy user, business, operational, or regulatory needs.
